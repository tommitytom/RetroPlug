# Codebase audit - 2026-09-20

Read-only survey of the RetroPlug tree (excluding `deps/`), covering the native C++
core, the four hosts (plugin / sdl / cli / node), the TS core, the LVGL UI, the CLI
SDK + test runners + tools, and docs / build / CI / hygiene. Every finding marked
**verified** was re-read at the cited location by a second pass; the rest were
reported by the area audit with quoted evidence and spot-checked but not independently
re-derived.

## Summary

The codebase is in better shape than most: the threading model (SPSC rings, triple
buffers, control-thread-owned allocation) is applied consistently, the zod + migration
story is coherent, the byte codecs are strict, and comments almost always say *why*.
TODO/FIXME density is 12 in ~135k lines. Bug density is low.

> **Status (2026-09-21):** all four clusters below are resolved, and all six items in the suggested
> order are done. The per-row residue - what was found but not fixed - is inventoried under
> [What is left](#what-is-left-2026-09-21) at the end of this file, which is the section to read if
> you are picking this up. The prose below is the original survey, kept as written.

The debt clusters in four places:

1. **Persistence edges.** Atomic writes exist, but the three writers of data the user
   cannot regenerate (thin project save, both SRAM flushers) do not use them, and every
   core-teardown path drops unsaved SRAM without a flush or a prompt.
2. **A live SameBoy model switch corrupts the snapshot pipeline** the .sav autosave
   reads from. Verified end to end.
3. **Copy-paste across siblings.** The three Mesen systems (~350 duplicated lines), the
   four hosts (~250 lines of boot / glue in 2-4 copies, already diverging), the three
   `*AssetsRole` + three `*Serialization` + risa/BlipToaster menu actions in TS.
4. **What the tests prove.** ~18 native test files pass vacuously when a fixture under a
   hard-coded `/workspaces/...` path is missing (always, in CI), the harness has no skip
   directive, and `pnpm validate` cannot fail on a missing validator.

Docs: `AGENTS.md` identifiers all resolve; its rot is numeric (counts). `spec/06` and
`spec/07`, the two files agents are told to read first, both misdirect.

## P0 - data loss and crashes (all verified)

> **Status (2026-09-20):** all seven rows are now FIXED. Rows 2, 4, 5, 6 and 7 by audit item 1
> (bb73b876, 4746fbd5, 48c8a895, 507fadee); row 1 by the model-switch re-arm (c30e90d8); row 3,
> the teardown flush, by audit item 2 (51c7d105, 7139dd1a, b81ed9cf).
>
> An earlier version of this line claimed rows 2-7 were all done by item 1. That was wrong: row 3
> was explicitly out of item 1's scope and stayed open until item 2.
>
> **Correction to row 1, found while fixing it.** The claim that CGB->DMG returns WRAM/VRAM
> bytes because the SRAM offset is stale by a WRAM+VRAM delta is **wrong**.
> `stateSnapshotRegions` derives the SRAM offset by subtracting vram, ram and mbc from
> `GB_get_save_state_size_no_bess`, and that total itself contains `+ ram_size + vram_size`,
> so the two terms cancel exactly: `Sram.offset == fixedSections + sgbBlock`. A DMG<->CGB
> switch does not move the SRAM offset, and the SRAM size is cart-derived so it never moves
> either. What actually moves is the total blob size (by exactly 0x8000), the Ram/Vram
> offsets and sizes, and — only across an HLE-SGB model — the SRAM offset, by about 74 KB.
> So the dominant symptom is a permanent FREEZE of readState/readSram (measured: a dmgB
> system's state stays at 181776 bytes when it should become 214544 on cgbC), which stops
> the .sav mirror tracking the battery and makes a project export capture a savestate the
> new model cannot restore. A wrong-bytes slice is reachable, but only via an SGB
> transition. Both are fixed.
>
> **Also fixed, found on the way:** the same freeze existed in the **Mesen** backends for a
> different reason. Their savestates are zlib-deflated, so size follows ENTROPY, not shape —
> and all three sized their slot from a state captured at construct, i.e. a console that had
> booted but not run, whose RAM is nearly all zeros. Measured on GBA: uncompressed 457369 at
> boot and warm (stable), compressed 27485 at boot but 97920 in play. So the ceiling came out
> at 49 KB against a state reaching ~98 KB, and every publish past that was skipped —
> `readState` frozen on the boot snapshot for the life of the system. NES and SMS escaped
> only because their states barely compress (~0.8x), so the 1.5x factor happened to cover
> them. The ceiling is now measured from an uncompressed serialize, which is
> entropy-independent, in one shared helper instead of three copies of the same wrong
> formula. Cost: GBA goes from a 49 KB ceiling to 580 KB (~3.3 MB resident per system); NES
> is unchanged at 1.04x.

## P1 - bugs worth fixing soon

> **Status (2026-09-21):** every row below was re-read at its cited location today. Eight are fixed;
> the rest are open and still reproduce. The fixed ones: the NES/GBA step loops (item 5, though not
> as this section described - see the row), the sav-suffix collision and `flushOnSave` (items 1-2),
> `reaper:mgb-smoke`'s missing assertion (item 4), the SDL Shift key and the `std::system` path
> injection (item 5), and, on the host side, the per-event allocation in the MIDI-**out** loop, which
> now copies into the DPF event rather than building a vector.
>
> **What is open splits into three groups.** Two are memory-safety bugs on the audio thread and are
> the ones worth doing next: `stageControllerMidi`'s 4-byte copy against a `len` it sets from the
> full size, and `NesEverdriveFifo`'s throwing `is_directory` inside a Mesen memory handler. One is a
> correctness bug with a data-loss shape: `swapRom` carrying the old cart's battery into the new
> cart's `.sav`. The remainder are quality issues - a non-atomic `gainDb_`, a leaked `JSContext*`
> slot per instance, silent file-op failures in the menu, several test/tooling paths that pass when
> they should not.
>
> Nothing here is a regression from items 1-6; these are the rows those items never claimed.

**Native core**
- FIXED (audit item 5), but not as described. Both loops are bounded now, with DIFFERENT bounds, because SMS's `kInstructionBudget` transfers to neither. NES gets a budget derived from the block: SMS's flat 80000 is quoted as "~10x headroom" for one block size and is only ~3.5x on NES at 2048 frames, where it would truncate blocks rather than backstop them. GBA cannot use an instruction budget at all - its loop unit is a whole video frame, so 80000 iterations is ~22 minutes of emulated time - and its genuinely unbounded loop is `GbaConsole::RunFrame` inside the vendored core, which nothing here can reach. The stated trigger is also wrong: `GbaApu::InternalRun` appends a sample per tick OUTSIDE its enabled-check, so a silent ROM still terminates the loop.
- `EngineInvoker.cpp:74-82` `stageControllerMidi` sets `len = bytes.size()` but copies 4 bytes; `drainInto` (`:181`) reads `data..data+len` past the union for any message > 4 bytes. Only the RPC entry guards it.
- `EngineInvoker.cpp:13-36` vs `EngineRpcService.cpp:87-101`: on a full command ring, `adoptSystem`/`replaceSystem` delete the freshly built core and `removeSystem` is dropped silently, after `constructSystem` already returned `true` to TS. `freePending` never deletes `stageSystemMidi.ext` (leak at teardown).
- `NesEverdriveFifo.hpp:865-874,913-915,1169-1170`: `de.is_directory()` is the throwing overload, called inside a Mesen memory handler on the audio thread with `_mutex` held; an escape is `std::terminate` in the DAW. The rest of the file uses `error_code` overloads.
- `HostSyncTrace.hpp:851,991` plain `static unsigned instances` incremented per `Engine` ctor; `RenderJobRegistry` constructs Engines on concurrent job threads (data race, diagnostic path only).
- `HostRpcService.cpp:52-59,74-78` `readFile` sizes from `fs::file_size` then reads (TOCTOU); a mid-read error returns the partial prefix as success.

**Hosts**
- `PluginDSP.cpp:329-336` drops every kernel MIDI-out message > 4 bytes although DPF supports `dataExt`; SysEx from LSDj passthrough / control surfaces never reaches the DAW. `sdl/main.cpp:969-971` explicitly calls this out, and `CMakeLists.txt:1393-1394` keeps Launchpad out of the plugin because of it.
- `sdl/main.cpp:1015-1016,1021` `Pa_StartStream` / `Pa_StopStream` return values ignored after `setAudioThreadOwns(true)`; if the stream fails, nothing drains the command ring, pushes become drops after 256 entries, and the fallback pump is not started. App looks alive with a dead emulator.
- PARTLY FIXED. The MIDI-**out** loop copies straight into the DPF event now. `PluginDSP.cpp:309` still builds a `std::vector` per inbound MIDI event on the audio thread, in a plugin declaring `DISTRHO_PLUGIN_IS_RT_SAFE 1`.
- `PluginDSP.cpp:145` `getUniqueId()` returns `RPgf` while `DISTRHO_PLUGIN_UNIQUE_ID` is `RPlg`; VST2/VST3 use the override, AU uses the macro. `DistrhoPluginInfo.h:157-160` says `RPlg` is canonical for both.
- `PluginDSP.cpp:104,224,340` `gainDb_` is a plain `float` written from main + audio thread (neighbouring `ccValue_` is atomic).
- `sdl/main.cpp:992-993` `static std::atomic<bool> tuned` latches for the first stream only; after `reconfigureAudio` the new callback thread never gets `tuneAudioThread()` (loses the A53 real-time headroom the comment says is needed).
- FIXED (audit item 5, 275add7e). `sdl/main.cpp` `feedKey` emitted `"key"` with 2 args where `PluginUI.cpp` emits 3 (the modifier mask), so Shift-typing in a prompt could not work in the SDL host - a filename typed there could not contain a capital. SDL now computes a DPF modifier mask (`dpfModsFromSdl`) and emits three args.
- FIXED (audit item 5, b5c9f100). Both hosts built `std::system("xdg-open \"" + p + "\" &")` by concatenation, so a path containing `"` or `$(` escaped the quoting - demonstrated live by opening `/tmp/$(touch /tmp/pwned)`, which created the file. - `cli/main.cpp:273,292`: SIGINT handler installed only after module eval; Ctrl-C returns exit 0, so an interrupted `retroplug-cli test` reports success.
- `PluginUI.cpp:561` + `ContextTargets.hpp:77`: `g_windowTargets` slots keyed by `JSContext*` are never erased (one leaked slot per instance; a reused address inherits the old slot).
